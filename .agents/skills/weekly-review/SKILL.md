# Weekly review

Use the user's private source profile or project instructions when provided. For setup, offer [the blank source profile](references/sources.example.md) and have the user keep the filled copy outside the shared repository. If no profile is available, proceed with sources the user has identified and ask only for details that materially affect the review.

## Gather evidence

Resolve the review dates, timezone and collection cutoff. Read the existing review and template for prior intentions, unresolved questions and any entry in progress. Gather evidence from the user's scoped connections and look for meaningful developments outside the stated goals. Include past chats when explicitly in scope and accessible. Local files, notes and excerpts are optional supplements.

For consequential claims, distinguish plans, delivered work, outcomes, verified impact and user-reported effort. Separate source observations from user reports and interpretations. Use dated source links, flag contradictions and summarize material coverage gaps. Continue with available sources and ask a focused question when the answer would change the review.

Deliver a concise brief in the current chat or a user-approved private location. Include the date window, cutoff, key developments, progress against intentions, and open questions or gaps. Keep source access read-only. Once the brief is ready, wait for an explicit request to start reflection.

## Reflect

When asked to start reflection, use the relevant brief from this chat or the one the user points to. If the brief is missing or ambiguous, resolve which week and brief to use before starting. Open with one question about the user's experience. Follow their answer and bring in evidence selectively when it clarifies an event or tests an assumption. Check additional evidence during reflection when it materially changes the discussion.

When the user is ready to wrap up, propose a short weekly overview and a few priorities. Build on any existing entry using its template. Offer a separate longer note when an idea warrants it. Preview each external edit with its destination and apply it only after the user approves that specific draft and destination. Verify the applied edit. Keep private identifiers, excerpts, briefs and personal output out of shared artifacts.
