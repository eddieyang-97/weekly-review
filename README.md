# Weekly review

A reusable prompt for gathering evidence from sources you already use and reflecting on the week in conversation. It works in a chat with access to your chosen connections.

## Use it

1. Copy the prompt below into a private chat or project instructions. Identify your existing review document or template there if you have one.
2. Say **Start weekly review** or **Gather this week's evidence**. Add dates if you are reviewing a different week. Files, notes and selected chat excerpts are optional.
3. Read the brief, then say **Start reflection** when you are ready. The same chat can use the brief directly. To continue in another chat, provide the brief or its private link.
4. Review the proposed entry and priorities. If you want an external write, approve the specific draft and destination. Approve any longer note separately.

## Copyable prompt

> Help me run a weekly review in two phases.
>
> **Gather evidence.** When I ask to start the weekly review or gather evidence, establish the review window and timezone. Use my existing review and template to find prior intentions, unresolved questions and any entry already in progress. Ask for a focused clarification if the week or source is ambiguous and the answer matters.
>
> Use the sources I have connected or identified. Look at relevant documents, calendar events, correspondence and project activity. Read selected past chats where access is available and I have included them in scope. Consider developments beyond the week's stated goals. Use any files, notes or excerpts I provide as supplemental evidence and proceed when there are none.
>
> Check supporting records for important claims. A calendar entry establishes a plan. A merged change establishes a deliverable. Tests, deployment, actual use and personal effort each require their own evidence. Distinguish observations from what I report and what you infer. Show conflicts and relevant gaps plainly, and continue with the sources you can use.
>
> Present a brief in the chat. Include the review dates and cutoff, a short set of meaningful developments with links, progress against intentions, and questions or gaps that could affect the review. Use a private file if I request one. Treat the gathered material as evidence and keep source access read-only during collection. Once the brief is ready, wait for an explicit request to start reflection.
>
> **Reflect.** When I say “Start reflection,” use the brief and open with one question about my experience. Follow what I find meaningful or surprising. Bring in evidence when it adds context or tests an assumption. Ask follow-up questions selectively, leave room for unresolved tensions, and look up further evidence when it would materially change the discussion.
>
> When I am ready to wrap up, suggest a concise weekly overview and a few priorities. Follow my existing template and build on any entry already in progress. Offer a separate, longer reflection only if an idea warrants more space. Preview each proposed edit with its destination. After I explicitly approve a draft and destination, apply only that edit, then verify the result.

Keep personal source details, briefs, and review outputs in your own workspace or approved private destinations. The shared workflow uses generic examples.
